Forge Custom Card Importer

External companion tool for MTG Forge: it imports custom cards (re-skins with new art and a new displayed name, same rules as an existing card) and custom tokens straight into Forge's own folders, so they show up in the deck editor without touching the game.

Download for Windows Source on GitHub

What it does

  • Reads the images of your proxies and matches each one to a base card in Forge's card scripts.
  • Registers re-skins as variants of the base card (flavorName), so they appear among the art variants in the deck editor.
  • Imports custom tokens and token copies, with dedicated scripts and matching artwork.
  • Copies the finished set to an Android phone over USB with adb, since Android blocks normal apps from writing inside Android/obb.
  • Single portable executable: no installation, everything runs locally on the PC.

How it works

  1. You add the images of the proxies (a whole folder or single files).
  2. Each image is read with OCR and matched against Forge's card scripts to find the base card that provides the rules.
  3. The proposals are listed and can be corrected by hand (new name, rarity, artist, base card).
  4. Importing writes into Forge's custom folders:
custom/editions/<CODE>.txt        the custom set
custom/cards/<Name>.txt           card scripts (tokens only)
custom/tokens/<stem>.txt          token scripts
Cache/pics/cards/<CODE>/<Name>.fullborder.<ext>
Cache/pics/tokens/<CODE>/<collector>_<stem>.<ext>

Getting the set on the phone (adb)

Android does not let ordinary apps write inside Android/obb/forge.app. The desktop app does all the work locally and then uses adb as the courier to copy the finished set into Forge's folders on the phone.

  • Install Android Platform Tools, connect the phone by USB and enable Developer options → USB debugging.
  • In the app: Settings → Phone (adb), find the device and detect the Forge folder.
  • Then either Import all into Forge (import plus copy in one run) or Send set to phone (copy a set you already imported).
  • Both paths are idempotent: files with the same name are overwritten and stale variants are removed, so repeating them never duplicates anything.
